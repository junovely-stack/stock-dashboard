# 시장 일지 · 복기 — 계획과 효율 설계

## 결론부터

"매일 느낌을 적어서 나중에 복기"만 하면 6개월 뒤에 남는 건 합리화된 일기장이다. 효율이 나려면 세 가지를 바꿔야 한다.

| 그냥 일지 | 이 시스템 |
|---|---|
| 수치를 손으로 옮겨 적음 (10분) | 수치는 전부 자동. 사람은 느낌 1 + 예측 1 + 근거 한 줄 (30초) |
| 기록이 쌓일 때까지 몇 달 기다림 | 2017년부터 백필 → **첫날부터** "알트 강도 X일 때 이후 30일" 확인 가능 |
| "그때 그런 느낌이었지" 서술형 복기 | 예측에 방향·기간·확신도를 박아두고 **자동 채점** → 적중률·과신 여부가 숫자로 나옴 |

## 무엇이 되고 무엇이 안 되나 (먼저 밝혀둠)

**되는 것**
- 지금 시장이 어느 구간인지 10개 지표로 한눈에 (알트 강도, 공포탐욕, BTC 200일선, ETH/BTC, 달러, 금리, VIX, 스테이블코인, 김프, 중소형주 상대강도)
- 과거에 같은 구간이었을 때 BTC·ETH·알트·나스닥·러셀·코스피·코스닥의 7일/30일 뒤 수익률 분포, **기저율 대비 몇 %p 차이인지**
- 여러 조건이 동시에 맞았던 날("지금과 비슷했던 날")과 그 구간 목록
- 내 예측 적중률, 확신도별 실제 적중률(과신 체크), 내 느낌별 이후 BTC 성적

**안 되는 것**
- 가격 예측. 나오는 건 "과거에 이랬을 때 상승확률 60% (평소 54%)" 같은 기울기뿐이다.
- 2017년 이후 코인 사이클은 사실상 2~3번이다. "지금과 비슷했던 날" 200일이 나와도 구간(에피소드)은 3~5개일 수 있다. 화면에 구간 수를 크게 띄운 이유.
- 매일 겹치는 30일 수익률이라 300일 표본 ≈ 독립 표본 10개. 카드마다 "독립≈"을 같이 보여준다.
- 알트 바스켓은 지금 살아남은 20종이라 과거 성과가 실제보다 좋게 나온다(생존 편향).
- 뉴스·지정학 이슈 자체는 수치화 안 한다. 일지의 "오늘 본 이슈"와 태그(FOMC, CPI…)로 사람이 남기고, 쌓이면 태그별 성적으로 본다.

## 구조

```
[매일 KST 09:20 · GitHub Actions]                      [폰에서 30초 · GitHub 이슈 폼]
 journal/collect.py  ─ Yahoo·alternative.me·           "📝 오늘의 시장 일지" 작성
   DefiLlama·Upbit·CoinGecko 전체 재추출                        │
        │  data/market/raw.csv, status.json                     ▼
        ▼                                              journal/ingest_issue.py → entries/*.json
 journal/analyze.py  ─ 피처 → 구간 → 조건부 통계                 │
   → 일지 채점 → dashboard.json, briefing.md  ◀──────────────────┘ (이슈에 결과 댓글 달고 닫음)
        │
        ▼
 journal.html (GitHub Pages) ── 1 지금 어디 / 2 비슷했던 날 / 3 구간표 / 4 흐름 / 5 내 일지
        │
        ▼
 briefing.md 복사 → Claude + docs/PROMPT.md 의 복기 프롬프트 → 해석만 받음
```

설계 판단
- **매일 전체 재추출**: 증분 수집은 하루 빠지면 구멍이 남는다. 매일 2017년부터 다시 받으니 Actions가 며칠 죽어도 다음 실행에서 자동 복구.
- **소스별 실패 격리**: Upbit가 막혀도 나머지는 갱신, Upbit 값만 "과거값" 칩으로 표시. Yahoo가 죽으면 워크플로를 실패 처리 → GitHub가 메일로 알려줌.
- **품질 게이트**: 행 수가 직전보다 5% 넘게 줄거나 BTC 최신일이 뒤로 가면 저장 안 함. 조용히 틀린 숫자가 올라가는 게 최악이라서.
- **계산은 코드, 해석은 Claude**: LLM에 수익률 계산을 맡기면 틀린 숫자를 자신 있게 말한다. `briefing.md`에 숫자를 다 박아서 넘긴다.
- **일지 = GitHub 이슈**: 서버·DB 없이 폰으로 입력 가능. 저장소 주인이 쓴 이슈만 처리(공개 저장소라도 남의 글이 페이지에 안 올라감).
- **사후 기록 제외**: 날짜를 과거로 적거나 24시간 지나 수정한 일지는 표시는 하되 적중률에서 뺀다.

## 운영 루틴 (이게 효율의 전부)

| 언제 | 뭘 | 시간 |
|---|---|---|
| 매일 아침 | `journal.html` 1번 카드 훑기 → 이슈 폼으로 일지 1건 | 1~2분 |
| 큰 이벤트 날 (FOMC·CPI·급락) | 일지 태그에 이벤트명. 예측은 7일로 짧게 | +30초 |
| 일요일 | 5번 "내 일지"에서 빗나간 것만 + PROMPT.md 주간 복기 | 10분 |
| 월 1회 | 30건 넘으면 월간 패턴 프롬프트, 구간 경계값 조정 검토 | 20분 |

일지는 "매일 쓰기"보다 **"쓸 때는 반드시 예측 1개"**가 중요하다. 3일에 한 번이라도 채점 가능한 기록 100건이 느낌만 적은 365건보다 낫다.

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 자동 수집·백필, 10개 지표 구간 통계, 비슷했던 날, 일지 입력·자동 채점, 복기 페이지, 브리핑 텍스트 | **이번에 구현** |
| 2 | 외국인·기관 순매수(코스피/코스닥), 선물 펀딩비·미결제약정, FOMC·CPI 일정 자동 태깅, FRED 순유동성 | 연동 대기 (아래 이유) |
| 3 | 일지 60건+ 쌓이면: 태그별 성적, 내 느낌 vs 공포탐욕 괴리 신호, 텔레그램/메일 아침 알림 | 데이터 쌓인 뒤 |
| 4 | 조건 조합 자동 탐색(어떤 지표 조합이 기저율을 가장 크게 벗어나나) | 3단계 후. 표본이 작아 과적합 위험 큼 |

2단계를 뒤로 뺀 이유
- **외국인 순매수**: 무료 소스가 네이버 금융 스크래핑뿐인데, GitHub Actions 서버(미국)에서 막힐 수 있고 페이지 구조가 바뀌면 조용히 틀린 값이 들어온다. 실제 네이버 화면 숫자와 며칠 대사한 뒤 붙이는 게 맞다. 이 저장소 `data/scraper/`에 예전 네이버 스크래퍼가 있다가 yfinance로 바뀐 흔적도 있다.
- **펀딩비**: 바이낸스·바이빗 API가 미국 IP를 차단한다(451). OKX 등 대안 소스 확인 필요.
- 화면에는 이 두 개를 "연동 대기" 칩으로 띄워둠.

## 처음 켜는 법 (5분)

1. 이 브랜치를 main에 머지 (스케줄 워크플로는 기본 브랜치에서만 돈다)
2. 저장소 **Settings → Pages** → Source: `Deploy from a branch`, `main` / `/ (root)` (이미 index.html 대시보드를 Pages로 보고 있으면 생략)
3. **Actions → 🧭 Market Journal (daily) → Run workflow** 한 번 수동 실행 → 1~3분 뒤 `data/market/raw.csv` 커밋되면 백필 완료
4. `https://<아이디>.github.io/stock-dashboard/journal.html` 열어서 상단 칩이 전부 초록이면 정상
5. **＋ 오늘 일지 쓰기** → 폼 작성 → 1분 뒤 이슈에 "✅ 일지 기록됨" 댓글 + 자동으로 닫히면 정상

첫 실행 때 확인할 것
- 상단 칩 중 빨강/노랑이 있으면 마우스 올려서 에러 확인. Upbit(김프)이 미국 서버에서 막히는 경우가 있을 수 있음 → 김프 카드만 "연동 대기"로 남고 나머지는 정상 동작.
- 알트 강도 현재값을 blockchaincenter.net Altcoin Season Index와 한 번 비교. 정의가 다르니(상위 50 vs 대형 20종) 숫자는 달라도 방향은 비슷해야 한다.

## 설정 바꾸는 곳

| 바꾸고 싶은 것 | 파일 · 위치 |
|---|---|
| 수집 종목, 알트 바스켓 구성 | `journal/collect.py` 상단 `YF_TICKERS`, `ALT_BASKET` |
| 지표 구간 경계 (예: 공포탐욕 25/45/56/75) | `journal/analyze.py` 상단 `INDICATORS` |
| "비슷했던 날" 조건 | `analyze.py` `ANALOG_KEYS`, `ANALOG_MIN_DAYS` |
| 횡보 판정 폭 | `analyze.py` `FLAT_BAND` (이슈 폼 설명 문구도 같이) |
| 예측 대상·기간 | `analyze.py` `TARGETS`/`HORIZONS` + 이슈 폼 + `ingest_issue.py` 매핑 |
| 실행 시각 | `.github/workflows/market-journal.yml` cron (UTC) |
