정반 배치 최적화 — 투입 순서만 바꿔도 지연이 줄어드는가

가짜 블록으로 만든 체감용 화면이다. 위가 지금 방식, 아래가 최적화이고 배치 규칙은 같고 블록 투입 순서만 다르다.

지금 방식착수 가능한 순서대로, 가장 먼저 비는 자리에 놓는다
최적화같은 규칙으로 놓되, 지연이 가장 적어지는 투입 순서를 찾는다
▶ 최적화 실행을 누르면 여기에 배치가 그려진다
요구일 안에 완료 요구일 넘김 (빗금 = 넘긴 기간) 가로 = 날짜(D+일) · 세로 = 정반 길이 방향 위치(m) · 블록에 마우스를 올리면 양쪽에서 같은 블록이 표시된다

이 화면이 보여주는 것

같은 블록·같은 정반·같은 배치 규칙에서 투입 순서만 바꿨다. 지연이 줄어든 만큼이 순서를 사람이 정할 때 놓치는 몫이다.

실데이터로 가는 순서

  1. MES에서 블록 길이·작업일수·착수 가능일·요구일, 정반 크기를 뽑는다
  2. 지난 3~6개월 실적으로 실제 배치 vs 최적 배치를 다시 계산한다
  3. 차이(지연 블록·정반 점유율)를 대시보드에 띄운다
  4. 주간 추천 배치안을 반장이 확인하고 쓴다

데모에 빠진 것

  • 크레인 동선·반전 공간·통로 제약
  • 블록 폭(실제는 정반 위 2차원 배치)
  • 작업반 인원·자재 지연·설계 변경
  • 실제 엔진은 Python OR-Tools CP-SAT(무료). 데모는 브라우저용 간이 탐색이다

먼저 확인할 것

  • 에스야드 블록 스케줄링이 조립 정반 단위까지 하는지
  • 실제 정반 위치가 MES에 남는지 (없으면 수기 수집부터)
예시 데이터로 만든 체감용 화면이다. 화면의 숫자는 실제 효과가 아니다. 실데이터 연결 지점은 소스의 genData()이다.
