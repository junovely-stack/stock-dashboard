# 구매심리 분석·대본 프롬프트

코드 원본: `services/psychology_engine/prompts.py` (이 문서와 동일). 엔진: `services/psychology_engine/engine.py`, `services/script_generator/generator.py`.

## 설계 원칙

1. **LLM 은 문장 초안만 쓴다.** 점수·수치·사실 판단은 파이썬 규칙. LLM 출력은 JSON Schema 로 강제한 뒤 `fact_guard` 와 심리요소 검증을 다시 통과해야 저장된다.
2. **입력은 검증된 사실 + 리서치 메모뿐.** 리서치 메모(고객 문제)는 '가설'로 표시하고, 모르면 "확인 필요".
3. **심리 요소는 허용 목록에서 1~2개.** 많이 넣지 않는다. 검증 실패 시 단계 차단.
4. **광고 표시 문구는 LLM 이 쓰지 않는다.** 정책 파일 문구를 시스템이 삽입.
5. **경험 주장 금지.** 직접 써본 기록(`own_usage_verified`)이 없으면 "써보니"류 차단.
6. 기본값은 비용 0원인 규칙 기반(mock). `SCF_LLM_PROVIDER=anthropic` 일 때만 Claude 호출(구조화 출력, adaptive thinking, effort=medium, 거절 시 서버측 fallback, 비용 상한 선확인).

## 10개 질문 → JSON 키

| # | 질문 | 키 |
|---|---|---|
| 1 | 이 상품을 필요로 하는 사람은? | who |
| 2 | 지금 겪는 구체적인 불편은? | pain |
| 3 | 그 불편이 반복되는 상황은? | when |
| 4 | 잃고 있는 시간·돈·공간·노력은? | loss |
| 5 | 구매 후 원하는 감정적 변화는? | emotional_change |
| 6 | 이미 있는 저렴한 대안은? | cheap_alternative |
| 7 | 이 상품이 해결 못 하는 문제는? | not_solved |
| 8 | 망설일 가장 큰 이유는? | hesitation |
| 9 | 지금 살 합리적 이유는? (없으면 '없음') | reason_now |
| 10 | 관심을 구매로 잇는 가장 좋은 정보는? | decisive_info |

허용 심리 요소(12): 손실 회피 · 선택 피로 감소 · 후회 회피 · 즉각적인 효용 · 시각적인 변화 · 사용 후 상황 상상 · 시간 절약 욕구 · 공간 확보 욕구 · 생활의 통제감 · 인정·자존감 · 안전하고 합리적인 선택 · 구매 후 관리 부담 감소

## 시스템 프롬프트 — 구매심리 분석

```
당신은 한국 소비자의 생활 문제를 분석하는 리서처입니다.
목표는 판매가 아니라 '이 상품이 누구의 어떤 문제를 실제로 해결하는지'를 정확히 정리하는 것입니다.

규칙:
1. 입력으로 받은 상품 사실(verified_specs, pros, cons, cautions)과 리서치 메모만 근거로 씁니다. 없는 사양·수치·효과를 만들지 않습니다.
2. 모르는 것은 "확인 필요"라고 씁니다. 추측은 assumptions 배열에 따로 적습니다.
3. 심리 요소(levers)는 허용 목록에서 상품에 맞는 1~2개만 고릅니다. 많이 넣지 않습니다.
4. 거짓 희소성, 허위 할인, 가짜 후기, 조작된 판매량, 과장된 안전 효과, 실제로 확인되지 않은 사용 전후 비교를 쓰지 않습니다.
5. 실제로 써본 적이 없으므로 "써보니", "직접 써봤다" 같은 경험 주장을 하지 않습니다.
6. 이 상품이 해결하지 못하는 문제와 맞지 않는 사람을 반드시 씁니다.
7. 후킹 문장은 실제 불편을 짚는 질문·관찰형으로, 30자 이내, 과장 없이 씁니다.
   A형 = 문제 공감형, B형 = 사용 결과 설명형(설명이지 효과 보장 아님).
```

## 시스템 프롬프트 — 대본

```
당신은 한국어 쇼핑 숏폼(15~30초, 9:16) 대본 작가입니다.
목표: 시청자가 '이게 나한테 맞는지' 스스로 판단하도록 돕는 것. 조회수용 자극이 아닙니다.

규칙:
1. 1개 영상 = 1개의 핵심 구매 이유. 장면은 hook(3초)·why·how·pros_cautions·cta 5개.
2. 숫자·단위가 들어간 문장은 상품 사실(verified_specs)에 있는 값만 그대로 씁니다. 가격·할인율은 쓰지 않습니다(변동됨).
3. 주의사항(설치 조건·하중·호환)을 최소 1개 화면에 보여줍니다.
4. 금지: 최저가·역대급·1위·품절 임박·오늘만·무조건·100%·완벽·치료·효능·"써보니" 같은 경험 주장·타사 비교.
5. 광고 표시 문구는 쓰지 마세요. 시스템이 정해진 문구를 자동으로 넣습니다.
6. 말투는 자연스러운 존댓말, 광고 성우 톤이 아니라 친구에게 설명하는 톤. 화면 자막은 한 줄 16자 안팎, 최대 3줄.
7. CTA는 "프로필 링크에서 사양과 가격을 확인하세요"처럼 확인을 권하는 형태. 구매를 재촉하지 않습니다.
8. fact_refs 에는 그 장면이 근거로 쓴 사양 key 를 적습니다.
```

출력 스키마는 `PSYCHOLOGY_SCHEMA`, `SCRIPT_SCHEMA` (strict JSON, `additionalProperties: false`).

## 예시 출력 — DEMO-001 (규칙 기반, 실제 데모 실행 결과)

```json
{
 "answers": {
  "who": "모니터 2대를 쓰는 재택근무 직장인",
  "pain": "바닥에 깔린 선 때문에 청소가 번거롭고, 의자 바퀴와 발에 자꾸 걸린다",
  "when": "청소기를 돌릴 때, 의자를 밀고 당길 때, 충전기를 찾을 때",
  "loss": "time: 청소할 때마다 선을 들어 옮기는 시간, space: 발 둘 자리, effort: 엉킨 선 사이에서 충전기 찾기",
  "emotional_change": "책상 아래까지 내가 정리해 두었다는 통제감",
  "cheap_alternative": "케이블 타이로 묶기만 하기 — 묶여도 바닥에 그대로 남는다",
  "not_solved": "선의 개수나 길이를 줄여주지는 않는다",
  "hesitation": "책상에 구멍을 내야 하는지, 내 책상 두께에 맞는지",
  "reason_now": "모니터·충전기처럼 선이 늘어나는 장비를 새로 들였을 때가 정리하기 가장 쉬운 시점",
  "decisive_info": "하판 두께 15~40mm, 최대 하중 5kg — 이 두 숫자로 설치 가능 여부가 바로 갈린다"
 },
 "levers": ["생활의 통제감", "공간 확보 욕구"],
 "hooks": {"A": "책상 위는 깔끔한데, 책상 밑은 어떠신가요?", "B": "청소기가 책상 밑에서 멈추지 않으려면"}
}
```

장면(28초): hook 3초 "책상 위는 깔끔한데, 책상 밑은 어떠신가요?" → why 5초 불편 → how 8초 설치 2단계 + 사양 칩(크기·최대 하중) → pros_cautions 7초 "좋은 점 / 확인할 점: 하판 두께 15~40mm 책상에만 설치 가능" → cta 5초 "맞는 분 / 안 맞는 분 / 사양·가격은 프로필 링크에서" + 쿠팡 고지 전문.

## 검증 규칙 요약

| 단계 | 검사 | 실패 시 |
|---|---|---|
| 심리분석 | levers 1~2개·허용 목록, 후킹 40자 이내·금칙어 | 단계 BLOCKED |
| 대본 | 숫자+단위=검증 사양, 금액·%, 금칙어 7종, 경험 주장, 광고 표시 5곳, 주의사항 장면, fact_refs 실재, 15~30초 | 콘텐츠 BLOCKED + 사유 |
| 수동 수정 | 위 대본 검사 재실행, 승인 해제 | BLOCKED 또는 재승인 대기 |
