# 기획안 재검토 — 자동화 관점

기준일 2026-11-18 · 지도: [SCF_온톨로지_REV02.html](SCF_온톨로지_REV02.html) (자동화 재검토 탭) · 가상 운영: [VIRTUAL_OPERATION.md](VIRTUAL_OPERATION.md) · 결정: [DECISIONS.md](DECISIONS.md)

## 결론

원 기획의 "사람이 매일 상품을 찾거나 편집하지 않아도 운영"은 **그대로는 불가능**하다. 상품 사양 최종 확인, 이미지 권리, 가격 재확인, 승인, 제휴 링크, (초기) 업로드, (앱 업로드 시) 성과 입력 — 이 7곳은 공식 API 가 없거나 사람이 판단해야 한다. 가상 운영 30일에서는 이보다 먼저 **상품 후보 공급**이 막혔다(D11 고갈, 20일 연속 미제작). 현실적인 최대치는 **"사람은 확인·승인만, 나머지는 자동"**이고, 지금 코드는 그 구조로 되어 있다. 남은 과제는 6곳에서 사람이 쓰는 시간을 줄이는 도구(등록 화면, 사양 추출, 승인 시간표)와 관측 Lv3(실패 알림·자가 복구)다.

## 5. 관측 성숙도 Lv2 → Lv3

- **현재 Lv2** — 연결된 파이프라인 + 스케줄 실행. 단계 상태·재시도·중복 방지·상류 실패 시 하류 건너뜀은 된다.
- **부족한 것** — ① 실패를 알리지 않는다(대시보드를 열어야 앎) ② 크래시 후 `running` 고착은 사람이 DB 를 고쳐야 풀린다 ③ 신선도 4신호 중 '행 수 전일 대비'와 '데이터 기준일' 검사가 없다.
- **Lv3 진입** — A23 실패 알림(D17 채널), A24 자가 복구(D2), 수집 단계에 행 수·기준일 검사 추가.
