## 왜 있나

이 시스템이 다루는 개념(키워드·고객 문제·상품·사양·콘텐츠·게시·성과…)과 그 관계를 한 장으로 고정해 둔다. 기능을 붙이거나 결정을 내릴 때 "어느 개념이 바뀌고, 그 개념은 지금 누가(사람/시스템) 만들고, 어디에 저장되며, 무엇이 막혀 있는지"를 먼저 본다.

## 읽는 법

- **영역 6 + 통제**: ① 수요 → ② 상품 → ③ 판단 → ④ 콘텐츠 → ⑤ 유통 → ⑥ 성과, 아래 띠는 통제·운영(정책·작업 큐·비용·감사·데이터 소스)
- **입력 유형**: 시스템 데이터 / 현장 실측 / 사람 확정
- **성숙도**: M0 수작업 / M1 도구화 / M2 자동실행 / M3 자동판정 / M4 예측
- **착수 단계**: 구현 완료 / 즉시 / 단기 / 중기 / 대상 외(사람이 계속)
- **데이터 상태**: mock / 수동 입력 / 연동 대기 / 내부 계산

## 핵심 경로 3개

1. **가치 경로** — 키워드가 고객 문제를 드러내고, 상품이 그 문제를 해결하고, 평가·선정이 하루 1개를 고르고, 콘텐츠가 플랫폼에 게시되고, 랜딩을 거쳐 성과가 쌓이고, 학습 보정이 다음 평가를 고친다. 마지막 고리(학습)는 귀속 데이터가 쌓이기 전까지 사실상 끊겨 있다.
2. **사실 경로** — 검증 사양 → 대본의 fact_refs → 사실 검사 → 승인 → 게시 게이트(사실 해시·영상 해시). 사양이 바뀌면 이 경로 전체가 다시 돌아야 한다.
3. **귀속 경로** — 플랫폼 → 랜딩(`?src=`, `?c=`) → 랜딩 이벤트 → 콘텐츠 / 제휴 링크(`sub_id`) → 제휴 실적. 메인 → 상품 이동 시 `src` 가 사라지는 결함이 있다(D2).
