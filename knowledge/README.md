# 조선소 조립공정 지식베이스

조립4과 생산관리 도메인 지식. **RAG에 전처리 없이 그대로 넣을 수 있는 코퍼스**가 원본이고, 사람이 읽는 통합본은 거기서 생성한다.

## RAG에 넣을 때

`rag/corpus_REV05.jsonl`을 그대로 인제스트한다. 전처리·청킹 불필요.

```json
{"id": "platen-02", "title": "...", "chapter": 6, "chapter_title": "정반", "type": "설비",
 "grade": "E", "rev": "REV05", "as_of": "2026-10",
 "aliases": ["핀지그", "pin jig", "고정정반", ...],
 "questions": ["핀지그가 뭐야", ...],
 "related": ["platen-01", "platen-04", "q-B5"],
 "text": "# 제목\n\n본문…\n\n근거 등급: …\n관련어: …\n이 항목이 답하는 질문: …"}
```

- **임베딩·BM25 대상은 `text`** 한 필드면 된다. 제목·본문·등급 문장·관련어·답하는 질문이 다 들어 있다.
- `grade`·`type`·`chapter`는 메타데이터 필터용. 예: `grade != "?"`만 검색하면 확정 지식만 나온다.
- 검색은 **하이브리드(BM25 + 임베딩)** 권장. 핀지그·오토캐리지·하이로 같은 고유명사는 임베딩만으론 약하다. 한글은 형태소 분석기 없으면 문자 bigram 토큰화로도 BM25가 잘 든다(이 코퍼스로 12문항 테스트 시 1위 적중률은 검증로그 참조).
- `related`로 인접 청크를 같이 가져오면(1-hop) 메커니즘 질문의 답이 좋아진다.

**시스템 프롬프트에 넣을 두 줄:**
> 검색된 항목의 "근거 등급"이 확인 대기(?)이면 그 값을 추정하지 말고 "사내 확인 전 항목"이라고 답하라.
> 근거 등급이 업계통용(G)이면 "일반적으로"를 붙여 답하라. 외부검증(E)·사내확정(C)은 그대로 답하라.

## 등급

| 표기 | 뜻 | 취급 |
|---|---|---|
| E | 외부검증 — 공개자료 2건 이상 교차확인 | 그대로 인용 |
| G | 업계통용 — 출처 단일 또는 구두 전승 | 사내 문서에 쓸 때 한 번 확인 |
| C | 사내확정 — 담당자 확인, 확인일 기록 | 그대로 사용 |
| ? | 사내확인필요 — 야드·과마다 다름 | **값을 채우지 않는다.** 질문 청크(q-*)가 "추정 금지" 지침을 품고 있다 |

## 청크 고치거나 추가하기

1. `rag/chunks/`에서 해당 `.md`를 고친다. 새 청크는 `id`를 파일명과 같게 하고 프론트매터 필수 필드(id·title·chapter·chapter_title·order·type·grade)를 채운다.
2. 규칙 — **청크 하나로 완결될 것.** "N절 참조" 금지(요지를 다시 쓴다), 본문에 `[E]`/`[?]` 약식 표기 금지(등급은 프론트매터), 표는 청크 안에 통째로, 본문 900자 넘으면 나눈다.
3. `py tools/rag_build_REV01.py` 실행 → 마지막 줄 `검증 통과 · 청크 N개`면 OK. 오류가 나면 파일명과 이유를 알려준다.
4. 생성물(JSONL·통합본)은 직접 고치지 않는다.

## 갱신 규칙

- 지식 내용이 바뀌면 빌더의 `REV`를 올린다 → 생성물 파일명이 함께 바뀐다.
- 등급 승격은 `검증로그`에 근거를 남긴 뒤 청크의 `grade`를 바꾼다. 사내 확인은 `?` → `C`(확인일 병기), 외부 자료 확보는 `G` → `E`.
- 사내 실제 코드·MES 스키마와 이 문서가 다르면 **실제 쪽이 정답.**
- 호선명·선주명·작업자 실명·사번은 넣지 않는다.
