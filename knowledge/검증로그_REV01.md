## 1. 어떻게 검증했나 (그리고 무엇은 검증하지 못했나)

| 단계 | 방법 | 결과 |

| 사내 고유 | 야드·과·호선·시스템 고유값 | `[?]` 본문 33개소 → 아래 질문 34건 |

**검증하지 못한 것을 먼저 밝힌다.**

1. **MES 스키마는 전혀 검증 못 했다.** 이 문서의 데이터 매핑(8장)은 "이런 데이터가 있어야 한다"는 요구 명세이고, 실제 테이블·컬럼 유무는 확인 대기다.
2. **우리 야드의 물리 구성**(정반 수, 크레인 대수, 과별 담당 블록)은 전부 `[?]`다. 외부 자료로는 알 수 없다.
3. **접근 차단된 출처 2건** — 나무위키 `조선업/직종 및 세부 공정`, 삼성중공업 블로그 `조선소 작업용어 총정리`. 사내 프록시에서 egress 차단. 검색 요약 수준으로만 반영하고 모두 `[G]` 이하로 내렸다.
4. **현장 일본어계 통용어**(시아게·아시바·스미다시·구사비 등)는 의도적으로 사전 본문에 넣지 않았다. 야드·세대별로 의미가 갈리는 단어가 있어 외부 출처만으로 확정할 수 없고, 잘못 넣으면 AI가 그대로 인용한다. 사용자 확인 후 REV02에 별도 블록으로 추가 예정.

## 3. 자체 모순 점검

문서 내 상충 여부를 직접 확인한 항목:

| 점검 | 결과 |
|---|---|
| `W.L` 약어가 작업량과 수선 두 뜻으로 쓰임 | 충돌 확인 → 7-2절에 경고 삽입, 사전에도 양쪽 등재 |
| 3장 "대조립 자동화 낮음" ↔ 4-3 "오토캐리지가 불량률 레버" | 모순 아님. 오토캐리지는 직선 장거리 구간 한정 → 대조립 적용 여지가 작다는 점을 4-3에 명시 |
| 9장 "곡직 팀 압박은 오진" ↔ 4-7 "곡직은 기량 의존" | 양립. 기량 편차는 사실이나 물량 증가의 원인은 상류 → 두 문장 모두 유지하고 4-7 말미에 순서 명시 |
| 당일검사완료율 = A/(A+R) | **지표 구멍 발견**: 신청을 늦추면 R이 줄어 지표가 오른다. 분자·분모 정의만으로는 구분 불가 → 4-6에 "신청 건수 병기" 경고 삽입 |

> 마지막 항목은 이 작업에서 새로 짚은 것. 목표 98% 달성 보고 시 신청 건수 추이를 같이 안 보여주면 지표가 신청 지연으로 관리될 수 있다.
